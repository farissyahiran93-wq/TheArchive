# Game design v3 draft

## Core loop

Read a message or record → inspect its source → compare it against another artifact → form a theory → choose whether, how, and to whom to disclose → observe a credible response → update the case understanding. The player can leave and resume after any beat.

## Rules

- **Player agency:** A highlighted response is only a draft. The engine writes a player message on explicit Send. Branch effects attach to that committed action.
- **Information ownership:** The player ledger and each character ledger are separate. Knowledge changes require an authored source and a specific recipient. Private discoveries do not become group knowledge.
- **Relationships:** Trust, affinity, suspicion, and romance are separate values, clamped by future authored rules. A romance route is optional; mystery access cannot depend on it.
- **Evidence:** Collected and verified are distinct. UI should show source, timestamp, chain of custody, and contradictions without presenting speculation as certainty.
- **Pacing:** Delays serve conversational rhythm, not arbitrary waiting. Timers schedule stable event IDs; reload resumes the queue without duplicate messages.
- **Episode gate:** An episode unlocks only when its authored required events are delivered. Phase 00 has no canonical unlock requirements, so all episodes remain locked.

## Phase 00 playable boundaries

The test channel contains four NPC lines and one player choice. It is clearly labeled as development content and has no canonical knowledge or relationship effects. Search has three fictional entries, Maps three pins, and the phone's other apps disclose their current availability. The Archive screen is locked and reveals no future twist.
