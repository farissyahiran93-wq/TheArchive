## Save and rollout strategy

1. **Classify, do not infer.** Inspect actual saved route/revision, entry snapshots, completion events, recipient receipts, pending journal and Chapter 2 state. A scene number or matching title is insufficient. New-route flags must be absent from historical saves unless an explicit supported action creates a separate playthrough.
2. **Preserve the primary investigation.** Default Continue resumes its recorded graph. A future new-game operation can reuse the existing atomic `archiveAndReplaceGame` pattern after a clear reviewed choice; preserve `historical-save:` entries and revision conflict behavior. Optional migration should initially be avoided in favor of a fresh separate route.
3. **Map semantics explicitly if conversion is later requested.** An old S01 completion may preserve history but still cannot assert a new unseen fact. Old S04–06 and old C2 are structurally different; do not map them. New C1S07–10 need genuine new prerequisites and actual actions even where names match. Keep legitimate completed old S06 and delivered authorizations intact.
4. **No save-store reset.** Preserve IndexedDB `the-archive-reboot`, pending-write journal, preferences, historical archives, application ID/signer/origin and explicit restore flow. Never read/import/delete or migrate legacy localStorage `the-archive:game-save:v1` automatically. This plan creates no migration.
5. **Version content and queue state.** Store stable new-route node/event/fragment IDs and current graph/manifest revisions. Keep delivered text immutable. Rebase only relative replay deadlines using the existing pattern; never regenerate authorizations or deliver an entire missing queue on load.
6. **Gate activation.** A production default must only point to a route whose current segment is playable and approved, with an honest unavailable boundary thereafter. Future chapter Continue appears from actual completion and unlock events; merely opening its title cannot start dialogue, install software or reveal evidence.

## Validation and acceptance contract

For every future implemented phase, run the repository-required commands and report their actual exit results: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`. Focused tests support iteration; they do not replace the required completion checks. Do not quote a previous report's pass count as a new result. Build warnings and physical-device limits are reported separately from failures.

Meaningful new contracts should verify:

- **Content integrity:** exactly 5 chapters / 10 scenes each / 50 unique scene IDs; valid graph targets; every required clue reachable; optional refusal does not permanently block the mystery; no additional numbered scene for calls or side activities.
- **Agency:** selection never sends; package review never installs; notification never opens evidence; inspecting does not save/authenticate; private notes do not share. Every sensitive request/report has the required review and explicit Send.
- **Knowledge:** each statement is justified by a delivered receipt or the speaker's own witnessed event; departed Lucas receives no later group facts; Sophie consent is not group permission; Nora stays professional unless an actual authored invitation occurs.
- **Recovery:** fixed manifest totals and chapter checkpoints; external sources add zero units; same-record fragments merge deterministically; retries/reloads cannot double count; locked bodies and late reveals are absent from search, thumbnail, accessibility and notification projections.
- **Calls:** ring, answer, decline, miss, callback, interrupted transcript and background/resume; final warning actually heard before completion; completion/unlock idempotent and manual next chapter. No real telephony API required.
- **Compatibility:** fixtures for old first-three-scene variants, old article/Version History/Corrections Desk boundaries, actual current v2 S07–10, structural 11–18 and all historical C2 states; unchanged delivered history and legitimate completions; no untouched legacy-key access.
- **Durability:** draft/queue/install/recovery checkpoints, same-tab pending-write recovery, stale-tab conflict, corrupt saves, archive/restore, replay snapshots and delayed events across long suspension.
- **Presentation:** current phone widths including 320px, landscape, keyboard viewport, zoom/Back/focus, source-error fallback, accessible call controls and reduced-motion guidance. Preserve TRACE 2.0 design and flashing green dots with non-motion alternatives.
- **Ending:** Vivian attribution has independent corroboration; June remains deceased; Daniel rescued alive by Rachel's authorities; final gratitude and emotional closure are delivered; 100% processing does not upgrade unverified sources automatically.
