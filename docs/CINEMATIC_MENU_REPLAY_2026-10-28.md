# Cinematic menu and replay — implementation notes

The entry point is `GameEntry`, which hydrates the existing Zustand store before showing `MainMenu`. The menu and gameplay share `PhoneShell`; the supplied portrait video and a poster extracted from it are local assets. The application keeps the existing IndexedDB primary save, pending-write journal, dialogue runner and timer code. A development-only `gameplaytest` entry keeps the existing phone regression tests focused on gameplay.

The production library projects the integrated Chapter 1 scene plan and the final source-investigation registry. It includes Scenes 01–10; the Scene 05 snapshot key uses the current canonical conversation ID while the existing planning/storage IDs remain unchanged. The separate historical Chapter 2 route remains in the save and runtime, and is not listed as a new Chapter 1 scene. Add new integrated scenes to the underlying registries and update the adapter when their final runtime is available.

Snapshots are captured only when a real scene entry transition is committed. Each snapshot omits the snapshot collection, and is persisted in the same canonical save and revision transaction. Historical scenes without an entry snapshot are shown as replay unavailable. Replay validates the snapshot, drains outstanding canonical writes, rebases pending deadlines, and uses the same store actions and runner against temporary memory. The commit path does not stage or write replay data. Runtime suspension blocks stale UI cleanup and timer callbacks while leaving replay; after the phone unmounts, the original in-memory state is restored. Restart and reload are disabled while a replay is active. Personal notes are temporary in replay. Refresh reads the untouched canonical save. The completion overlay prevents proceeding to the next scene.

Settings for audio and the menu live independently of story progress. Typing speed affects newly scheduled NPC messages; authored waits retain their timing. Reduced motion respects the OS preference and the phone setting. Video is muted and inline, pauses on visibility changes and uses the extracted poster on playback failure or reduced motion.

Known limitations: historical saves cannot replay scenes whose entry was not captured, and the library currently covers the owner-requested Chapter 1 only. The existing phone UI returns through its lock screen when resuming, and some transient application navigation is not persisted independently of the existing story checkpoints. The older historical Chapter 2 content remains available through its existing saved route, not through this library. The production bundle retains Vite's existing large-chunk warning. No Android APK was rebuilt, and no commit or push was made.
