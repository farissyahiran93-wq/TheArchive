# IMPLEMENTATION REQUIREMENTS FOR CODEX

## 1. Preserve choice architecture

Scene 05 retains exactly 11 primary choice groups with 33 authored branches:

- C01–C07: Seven Unknown Number chat exchanges, three branches each.
- C08: Three optional Corrections Desk questions in Browser, introduced by Unknown Number.
- C09–C10: Two optional Sophie chat exchanges, three branches each.
- C11: One optional FIND DANIEL group exchange, three branches.

Pre-installation Unknown Number dialogue is a separate canonical bridge event, not an additional Scene 05 choice group.

## 2. Use actual Messages runtime

Unknown Number dialogue must use the same data-driven conversation infrastructure as Sophie, Maya and other characters.

Each player response must:

- Be selected manually.
- Be staged in the composer.
- Require SEND.
- Be inserted once into chat history.
- Trigger only the appropriate authored reply.
- Survive save/reload.

Do not insert a prewritten player reply automatically.

Do not render the conversation as fake chat screenshots or standalone Archive questionnaires.

## 3. Source-aware conversation gates

Use actual interaction completion events:

`article_metadata_inspected`

`arc_idx_gb_041_inspected`

`bulletin_policy_read`

`required_verification_gaps_reviewed`

Do not allow Unknown Number to reference a player's private screen actions as knowledge unless explicitly disclosed in a sent message.

Story-event eligibility may depend on inspected-source flags, but NPC wording must not imply unauthorized observation.

For example:

Allowed:

"There's an update label on the public page."

Not allowed without story justification:

"I saw you open the update metadata five seconds ago."

If the player investigates sources out of order, allow the conversation to resume coherently without resetting records.

## 4. Avoid quiz behavior

No right/wrong popup in Unknown Number chats.

If the player makes an unsupported claim, Unknown Number responds naturally, explaining its limitations.

Do not block the conversation behind repeated attempts to choose the supposedly correct answer.

Record the distinction between:

- Supported observation.
- Hypothesis.
- Question.
- Selected investigation strategy.
- Player's shared assessment.

All three branches at a conversation node must converge safely.

## 5. Browser integration

Use the existing in-game browser.

The Greyhaven article and Corrections Desk must be browsable through normal navigation.

Do not invent a real external domain.

Use the canonical fictional publication data.

Return using normal Back navigation.

Preserve relevant previous screen state and chat scroll position.

## 6. Archive integration

Archive should display records and investigative progress.

It must not contain copies of the Unknown Number chat or a second dialogue runner.

The Version History workspace links to existing source data.

Use the canonical article and index records as the source of truth.

Use private notes for the player's stored assessment.

The fact that the player discussed an assessment with Unknown Number must not disclose their full notes to other characters.

## 7. Contact blocking removal

Globally remove Block Contact / Block Number behavior as specified in the prior implementation instructions.

Unknown Number must always be able to deliver legitimate story messages after legacy-save migration.

Preserve all history, relationships, notifications and chapter progress.

## 8. Save compatibility

Audit the current save schema and migrate safely.

Maintain separate durable states for:

- Unknown Number first contact.
- Archive package delivery.
- Voluntary installation.
- Initial index inspection.
- Scene 05 availability.
- Unknown Number conversation progress.
- Source inspection flags.
- Strategy and assessment.
- Corrections Desk request receipt.
- Optional Sophie/group conversations.
- Scene 05 completion.

Prevent duplicate message delivery and repeated installation.

Legacy saves with Archive already installed must not trigger forced reinstallation.
